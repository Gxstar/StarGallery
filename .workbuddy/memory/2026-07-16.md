## 详情页大图加载逻辑优化分析（结合 minSdk=30）

用户确认项目 minSdk 实际为 30（build.gradle.kts 中 minSdk=30，用户口述 31）。

### 当前流程
PhotoDetailFragment(ViewPager2, offscreenPageLimit=1) → PhotoDetailViewModel(init 优先读 PhotoDetailListCache 快照+后台 loadPhotosInBackground，SortUtils.sortPhotos 排序) → PhotoPagerAdapter.submitList(DiffUtil 仅比 id/uri/width/height/mimeType) → PhotoPageViewHolder.bind 分流：
- 视频→ExoPlayerManager(Media3 单例)
- GIF→Glide.asGif()
- 图片→loadImage()：HDR探测(仅jpeg&API34+)→checkHdrAndLoad；否则长边≥2000||isRaw→loadWithSubsampling(Glide 1200px 预览+ZoomImage子采样, AVIF 用自定义 AvifRegionDecoder)；否则 loadFullImage(Glide 全图)

### 发现的可优化点（已反馈用户，待确认是否动手）
1. P0 RAW 子采样是"假优化"：ZoomImage 无 image/x-* 解码器，AvifRegionDecoder 仅对 avif 生效，RAW 走 setSubsamplingImage 会黑屏/崩溃。建议 RAW 改用 contentResolver.loadThumbnail(uri, Size(1920,1920), null)（API29+，minSdk30✅）。
2. P0 HDR 分支仅认 image/jpeg|jpg，遗漏 HEIC/AVIF 的 gainmap HDR。建议放宽 shouldProbeHdr 的 mimeType 到 {jpeg,jpg,heic,heif,avif}，保留 hasGainmap() 运行时实测兜底。
3. P1 HDR 当前解码两次（200x200 探测 + 全图）。建议合并为单次全图解码后 hasGainmap() 判定。
4. P1 AvifRegionDecoder 每次 decodeRegion 整图解码再裁剪+copy，AVIF 软解大图吃 CPU/内存。可复用 cachedBitmap、减少 copy。
- 实测：HEIC 在 minSdk30 下 BitmapRegionDecoder 已支持(API28+)；AVIF 解码 API31+ 但 BitmapRegionDecoder 永远不支持 AVIF（自定义 decoder 原因正确）。
- 依赖：glide 4.16.0, zoomimage 1.4.0, media3 1.9.1。

## HDR isHdr 标签未正确显示 bug 修复

### 根因
`isHdr` 的权威数据来源是 `ExifExtractor.extractExif()` 的附属产物，但 `extractExif()` 有两个丢弃路径：
1. `isAllNull()` 返回 true 时直接 return null，丢弃已检测到的 `isHdr=true`
2. `ImageMetadataReader.readMetadata()` 抛异常时 catch 分支 return null，同样丢弃 `isHdr`
3. 增量/全量扫描入库时 `isHdr = exif?.isHdr ?: false` 依赖 DB 旧快照（新照片为 null→false），必须等 EXIF 异步提取完成才更新

### 修复内容（4 个文件）

**ExifExtractor.kt**：
- `isAllNull()` 检查增加 `&& !isHdr`：EXIF 字段全空但 HDR 命中时不丢弃
- catch 分支在 `isHdr=true` 时返回 `ExifData(isHdr=true)` 兜底
- `applyToEntity` 中 `isHdr = exifData.isHdr || entity.isHdr`（只允许 true 覆盖 false，不允许 false 覆盖 true）
- `isHdr` 变量提至 try 外部以在 catch 可见

**MediaScanner.kt**：
- 三个入库路径（全量/增量/syncSpecificPhotos）`isHdr` 改为 `detectUltraHdr(item.uri)` 实时检测
- 新增 private `detectUltraHdr(uriString)` 方法（仅 JPEG & API34+，读前128KB搜"hdr-gain-map"）
- `extractExifForAllPhotos` 末尾追加 `fixLegacyHdrLabels()` 修正旧数据

**PhotoDao.kt**：
- 新增 `getNonHdrJpegIds()` 查询（isHdr=0 的 JPEG 照片 ID 列表）

**PhotoPageViewHolder.kt**：未改动（上次建议评估后确认不需要修改）
