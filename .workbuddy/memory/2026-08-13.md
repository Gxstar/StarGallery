# 2026-08-13 工作日志

## 图片详情页大图加载流程核查（zoomimage 1.6.0 源码级验证）

用户要求核实详情页大图加载流程结论是否正确、是否需改进。通过解包本地 gradle 缓存中 zoomimage 1.6.0 sources jar 与 view-glide 的 classes.jar 字节码反编译，得出确定结论：

### 已证实的结论（上一轮分析正确）
1. `setRegionDecoders` 是**前置追加**语义：`createTileDecoder` 中 `regionDecoders.plus(defaultRegionDecoders()).find{accept}`，自定义解码器优先，默认 `AndroidRegionDecoder`（jpeg/png/webp=true, gif/bmp/svg=false, heic=API≥27, avif=API≥37）始终在后。
2. `checkImageInfo`：`contentSize >= imageSize`（小图）或宽高比不一致时抛异常 → 自动跳过子采样。
3. AVIF 双路径、JXL 直连（JxlCoder 绕 Glide content://，因 MediaStore 缩略图 setDataSource 失败）、色彩模式按位图实际属性（gainmap/PQ/HLG/wide gamut）判定均正确合理。

### 决定性新发现（比上一轮更进一步）
**主详情页子采样确认失效（非"可能"）**：反编译 `GlideZoomImageView.resetImageSource()` 字节码确认——
- drawable 变化后 post Runnable：`GlidesKt.getRequestFromView(view)` 取 view 上的 Glide Request → `getInternalModel(request)` 取 model → 仅当 `request != null && request.isComplete() && model != null && drawable != null` 才遍历 `subsamplingImageGenerators` 调 `generateImage()` 生成 `SubsamplingImage`；
- **否则走 else 分支：`setSubsamplingImage(null)` 显式清除子采样**。
- 主详情页 `loadWithSubsampling`/`loadFullImage` 用 `CustomTarget` + 手动 `setImageDrawable`，view 上无 Glide Request → 子采样被显式清空，只显示单张位图。
- `TrashPhotoPreviewDialog` 用 `.into(binding.ivPhoto)`（标准用法）→ 子采样真正生效。`AvifRegionDecoder` 只在回收站预览路径 reachable。

### 改进建议（已给出，未改代码）
- P0：主详情页改回 `.into(binding.ivPhoto)` + `RequestListener`（onResourceReady 里拿 bitmap 做 `applyWindowColorMode`），或 CustomTarget 中显式 `setSubsamplingImage(...)`。
- P1：JXL 回收站预览走 Glide 全图无尺寸上限（主详情页有 4096 上限），可统一；`needSubsampling` 的 2000 硬编码可提常量、两处详情入口逻辑可抽公共。
- 合理保留：AVIF 原生探测→HDR/子采样/回退 libavif；JXL 直连；libavif 直连上限 2560（RGBA_F16 8B/px）。

### 关键事实备忘
- 实际版本：minSdk=35, targetSdk=36, compileSdk=37（AGENTS.md 中 minSdk 30 / ZoomImage 1.4.0 已过时），zoomimage 1.6.0, Glide 5.0.9, jxl-coder 2.6.1, avif-coder 2.2.1。
- `AndroidRegionDecoder.checkSupport("image/avif") = SDK>=37`，即 API 35/36 设备上 AVIF 子采样只能靠 `AvifRegionDecoder`（前置命中）。

## 详情页子采样修复（已改代码，编译通过）

用户批准动手修复。改动 2 个文件：

### 1. PhotoPageViewHolder.kt — loadFullImage / loadWithSubsampling 挂 view
- 原实现用 `CustomTarget` + 手动 `setImageDrawable` → view 上无 Glide Request → GlideZoomImageView 的 `resetImageSource()` 取不到 request/model → 走 else 分支 `setSubsamplingImage(null)` 显式清除子采样 → 子采样从未生效。
- 改为 `.into(binding.ivPhoto)` 直接挂 view，Glide 成功回调时 `getRequestFromView(view)` 能拿到 Request → 自动生成 SubsamplingImage 驱动子采样。
- 原 CustomTarget 里的色彩模式/进度条/updateEdgeState 逻辑挪进 `imageLoadListener`（RequestListener，onResourceReady 返回 false 交给 view 显示）。
- `jxlListener` 更名为 `imageLoadListener`；删除 CustomTarget/Transition import。

### 2. AvifRegionDecoder.kt — Factory.accept() 双保险探测
- 关键发现：`EngineGlideSubsamplingImageGenerator` 生成的 `SubsamplingImage(imageSource, null)` **imageInfo 恒为 null**，原 accept() 依赖 `imageInfo?.mimeType` → 永远 false → AVIF 子采样在 API<37 上仍不触发（即使挂 view）。
- 修复：mimeType 非空时用 checkSupport；为空时回退 `isAvifHeader(headerBytes)` 文件头探测（ftyp + avif/avis 主品牌 + mif1/msf1 兼容品牌查找），与库 AndroidRegionDecoder.Factory.accept 机制一致。
- 新增顶层私有函数 `isAvifHeader`。

### 修复后行为
- 大图 JPEG/PNG/HEIC（≥2000px 或 RAW）→ 默认 AndroidRegionDecoder 子采样真生效
- AVIF SDR 大图 → AvifRegionDecoder 子采样真生效（API 35/36 唯一路径）
- JXL → 仍走 loadJxlDirect 直连（禁用子采样）；HDR/AVIF 直连路径不变

### 遗留建议（未做，用户可后续确认）
- P1：TrashPhotoPreviewDialog 的 JXL 走 Glide 全图无 4096 上限，超大 JXL 有 OOM 风险
- P2：2000px 阈值三处硬编码、两详情入口逻辑重复，可抽公共

## 构建报错排查（compileDebugJavaWithJavac 失败）

现象：`:app:compileDebugJavaWithJavac` 报 `JdkImageTransform` 执行 `jlink.exe --version` 失败 / `Unable to delete directory .../compileDebugJavaWithJavac/classes`（文件被占用）。
根因：**非代码、非 JDK 问题**。jlink 手动执行正常、jmods 齐全（70 个）。是残留 Gradle daemon 或子进程持有 `app/build/intermediates/javac` 文件句柄，导致 AGP 的 JdkImageTransform 缓存失效后既无法重建 jdk image 也无法删除旧目录。
解法：`./gradlew --stop` 停 daemon → 删除 `app/build/intermediates/javac` → 重跑，BUILD SUCCESSFUL。
复用要点：再遇到 jlink transform / Unable to delete 类报错，先 stop daemon + 清对应 intermediates 目录，不必动 JDK。

## AVIF 放大变糊修复（第二轮，用户实测反馈）

用户实测：双击放大 AVIF 图片是糊的，之前清晰。根因（zoomimage 库机制源码确认）：
1. `TileDecoder` 有**解码器池**：瓦片并发请求时 `copy()` 出多个 decoder 实例，每个实例独立整帧软解 → 重复解码、内存爆炸、极慢
2. `AvifRegionDecoder` 是"整帧解码+裁切"的**模拟瓦片**：AVIF 无原生 region 解码，sampleSize 变化（放大）时每次整帧重解（~4096px RGBA_F16 100MB+，数百 ms~数秒）→ 瓦片迟迟加载不出来
3. 用户看到的其实是 Glide 的 fitCenter 预览图（屏幕尺寸）→ 糊；之前清晰是因为修复前子采样被清除、显示全尺寸位图

结论：**AVIF 不应走瓦片子采样**，与 JXL 一样禁用子采样、整图解码。

   - `loadAvifAdaptive` 的 SDR 分支（nativeProbe=false）不再走 loadWithSubsampling/loadFullImage，改为 `loadNativeFullImage`（ImageDecoder 整图解码，4096 上限，禁用子采样）
   - `loadHdrBitmap` 重命名为 `loadNativeFullImage`（AVIF SDR/HDR 与 HEIF/UltraHDR 通用），`checkHdrAndLoad` 同步更新
