StarGallery 平板显示适配性评估

评估对象：首页照片网格列表 + 图片详情页信息弹窗 · 评估日期：2026-08-14 · 关键文件：PhotosFragment.kt、GridSpanCalculator.kt、PhotoInfoBottomSheet.kt、fragment_photos.xml、themes.xml、AndroidManifest.xml
总体结论：能装、能跑，但完全是"放大版手机"，没有任何平板专属适配。
项目里不存在任何 sw600dp / sw720dp / w600dp 限定符的布局或 dimens 资源，只有 layout/ 与 layout-land/（横屏手机）。首页网格靠"按屏宽算列数"勉强撑住了大屏，但详情页信息弹窗在平板上会全宽拉伸，是体验硬伤。

一、首页网格列表

✅ 已具备一定的大屏友好性（动态列数）
  • GridSpanCalculator.calculateOptimalSpanCount()：列数 = 屏幕宽度dp / 80dp，并 coerceIn(3, 10)。
  • PhotosFragment.showColumnsDialog() 允许用户手动选 3–8 列；GridSpanPreferences 支持竖/横屏分别记忆。
  • 旋转、列数切换都正确联动：onConfigurationChanged 重算 item 尺寸，Glide 预加载数与 ItemDecoration 同步重建。
⚠️ 问题 1：列数上限偏低，平板上浪费空间
  • 计算器 MAX_SPAN_COUNT = 10，但 UI 选择上限只有 8 列。11–13 英寸平板竖屏约 800dp，8 列 → 每格约 100dp，缩略图过大、稀疏。
  • 真正的大屏本可承载 10–12 列。建议把 UI 上限提到 12，并在 values-sw720dp 里把默认 fallback 调高（如默认 9–10 列）。
⚠️ 问题 2：没有主从（Master-Detail）布局
  • 平板首页仍是纯全宽网格，未利用大屏空间做"左侧相册/日期导航 + 右侧网格"，右侧大片空白被浪费——这是平板体验与手机最大的差距。
⚠️ 问题 3：间距/留白仍是手机尺寸
  • dimens.xml 中 grid_spacing=2dp、padding 16dp 等全部写死小值；item_photo.xml 用 layout_constraintDimensionRatio="1:1" 固定正方形，平板上会显得拥挤或留白不协调。

二、图片详情页信息弹窗（PhotoInfoBottomSheet）

🔴 严重问题：全宽底弹窗，无任何最大宽度限制
  • PhotoInfoBottomSheet.kt 是 BottomSheetDialogFragment，未重写 getTheme()（对比同项目的 DeleteOptionsBottomSheet 重写了主题）。
  • themes.xml 里的 CustomBottomSheetStyle 只设了 backgroundTint，没有 android:maxWidth。于是平板上信息弹窗从屏幕左缘拉到右缘，内容（相机/镜头/分辨率卡片、ISO·光圈·快门 三列参数、位置、风格）被横向拉伸，行间拉大、视觉稀疏难看。
  • 根布局 NestedScrollView 宽度 match_parent，padding 仅 20dp，正文在平板上横向铺满、阅读动线过长。
  • 讽刺的是：MainActivity.applyBottomNavWidth() 已经把底部导航栏做了 maxWidth 480dp 居中——说明开发者知道大屏要限宽，却没把同样的处理应用到信息弹窗。

三、其他平板相关点

  • 详情页 overlay 栏：fragment_photo_detail.xml 顶/底 overlay 均为 match_parent 全宽。底部操作栏（发送/信息/收藏/删除/编辑 5 个）在平板上横向铺满一整行，可改为居中固定宽度胶囊（同底栏做法）。
  • 二级页面：设置/关于等 Fragment 全宽，无约束，平板上可读性一般。
  • 横屏：已有 layout-land（首页、MainActivity），但仅解决"横屏不错位"，并非平板优化。
  • Manifest：未声明 supports-screens，默认放行所有尺寸（不会被 Play 过滤），但也意味着在平板上以兼容模式放大运行。

四、优先级修复建议

优先级问题建议方案改动量
P0 信息弹窗平板全宽拉伸 在 PhotoInfoBottomSheet 重写 getTheme() 指向带 android:maxWidth≈600dp 的 BottomSheet 主题；或 onStart() 里给 BottomSheetBehavior 设 maxWidth 并居中；内容宽度约束 560–640dp，参数卡片改为 2 列网格。 ~10 行
P1 网格列数上限低、无主从布局 UI 列数上限提到 12；新增 values-sw720dp 把默认 fallback 调高；评估是否上 sw720dp 主从布局（左导航 + 右网格）。 中等
P2 二级页面/详情 overlay 未限宽 详情 overlay 与设置等页面对大屏限宽居中；统一在 values-sw600dp / sw720dp 调整间距与字号。 中等
最低成本的一步：先给信息弹窗加 maxWidth 居中（约 10 行改动），即可消除平板上最刺眼的"全宽拉伸"。需要我直接动手改吗？
