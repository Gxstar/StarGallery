StarGallery 平板显示适配 — 修复记录

2026-08-14 · 针对 P0–P2 全部落地 · 编译状态：assembleDebug 通过
已修复此前评估发现的"平板=放大版手机"问题：信息弹窗全宽拉伸、网格列数上限偏低、无平板导航、详情/设置 overlay 全宽。

P0 底部弹窗（信息/筛选/删除）大屏限宽居中

问题BottomSheetDialog 在平板上从屏幕左缘拉到右缘，参数卡片被横向拉伸、行间拉大，视觉稀疏。
改动新增工具 BottomSheetWidthHelper.constrainBottomSheetWidth(maxWidthDp)：在 onStart() 内、当 screenWidthDp ≥ 600 时，将 design_bottom_sheet 容器限制宽度并以 Gravity.CENTER_HORIZONTAL 居中；手机保持全宽。
文件 ui/common/BottomSheetWidthHelper.kt（新增）
ui/detail/PhotoInfoBottomSheet.kt（480dp）
ui/photos/filter/FilterBottomSheet.kt（560dp，选项多）
ui/common/DeleteOptionsBottomSheet.kt（480dp）

P1 网格列数上限 8 → 12

问题用户可选列数上限仅 8，11–13 英寸平板上每格过大，浪费大屏空间（动态计算器本支持到 10）。
改动GridSpanCalculator.MAX_SPAN_COUNT 由 10 提到 12；首页与相册详情的列数选择弹窗改为按 (MIN_SPAN_COUNT..MAX_SPAN_COUNT) 动态生成，不再写死 3–8。竖横屏分别记忆逻辑不变。
文件 ui/common/GridSpanCalculator.kt
ui/photos/PhotosFragment.kt（showColumnsDialog）
ui/albums/AlbumDetailFragment.kt（showColumnsDialog）

P1 平板主从导航（左侧 NavigationRail）

问题首页底部 NavigationView 居中胶囊在平板上仍占底部空间，左侧大片区域未被利用作导航。
改动 在 activity_main.xml（含 layout-land 变体）新增 NavigationRailView（id navigation_rail，复用 bottom_nav_menu）；
nav_host 改为 constraintStart_toEndOf="@id/navigation_rail"（rail 隐藏时自动贴左）；
MainActivity.applyNavigationVisibility() 按 screenWidthDp ≥ 600 切换"侧边 rail / 底部 nav"，仅首页与相册列表显示，其余页面隐藏，旋转时重算。
文件 res/layout/activity_main.xml
res/layout-land/activity_main.xml
MainActivity.kt

P2 详情 overlay 与设置页大屏限宽居中

问题详情页顶部/底部工具栏、设置页内容在平板上全宽拉伸，按钮点击热区过大、选项行过长。
改动 PhotoDetailFragment.applyDetailOverlayWidth()：将 topBar / bottomBar 限制 640dp 居中（FrameLayout 子节点），旋转时重算；
SettingsFragment.applyContentMaxWidth()：将 CoordinatorLayout 子节点（顶栏 + 列表）限制 640dp 居中。
文件 ui/detail/PhotoDetailFragment.kt
ui/settings/SettingsFragment.kt

验证方法

  • 已通过 ./gradlew.bat assembleDebug（仅预存在的弃用警告，无错误）。
  • 用 w600dp / w840dp 的平板模拟器或开发者选项"最小宽度"切到 600+，验证：弹窗居中限宽、首页出现左侧导航 rail、列数可选到 12、详情与设置 toolbar 居中。
  • 手机（<600dp）行为不变：底部导航 + 全宽弹窗 + 列数 3–8。

判定阈值统一为 screenWidthDp ≥ 600；底部导航/弹窗限宽沿用既有 480dp 思路，overlay 用 640dp。其他二级页（关于/回收站/隐藏/相册列表/排除相册）仍为全宽，需要时复用同样的 constrainWidthCentered 模式即可。
